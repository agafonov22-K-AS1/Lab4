# Lab4
## Авторы: Агафонов Александр, Жданько Алексей, Пасеченко Иван.

### 1. Цели работы

1.1. Изучить архитектуру и принципы работы современных Command&Control фреймворков  
1.2. Развернуть C2-инфраструктуру на виртуальной машине Linux  
1.3. Сгенерировать полезную нагрузку и доставить её на целевую систему Windows  
1.4. Получить удалённый контроль над системой и изучить возможности постэксплуатации  

---

### 2. Ход работы

#### 2.1. Подготовка лабораторного стенда

В качестве платформы для C2-сервера использована виртуальная машина с Ubuntu Server 24.04. Для удобства управления установлена графическая среда Lubuntu. Целевой системой выбрана Windows 10, развёрнутая в отдельной виртуальной машине. Обе системы настроены в режиме сетевого моста с адресами 192.168.9.103 (Debian) и 192.168.9.63 (Windows), что обеспечило прямое сетевое взаимодействие.

#### 2.2. Выбор и установка C2-фреймворка

После анализа доступных вариантов выбран фреймворк Sliver C2 как современное решение с открытым исходным кодом. Установка выполнена через официальный скрипт.

#### 2.3. Настройка слушателя и генерация нагрузки

В интерфейсе Sliver создан HTTP-слушатель на порту 80. С использованием встроенного генератора создан исполняемый файл safetyfile.exe для 64-битной архитектуры Windows. Файл сохранён по пути /tmp/safetyfile.exe и имел размер 16.5 МБ.

#### 2.4. Доставка и выполнение полезной нагрузки

Для передачи файла на целевую систему развёрнут HTTP-сервер на порту 1488 с помощью Python. С Windows-машины выполнен переход по адресу ВМ хоста с соответствующим портом, после чего файл safetyfile.exe скачан в папку загрузок. Исполняемый файл запущен двойным кликом.

#### 2.5. Получение удалённого доступа

Через 10-15 секунд после запуска safetyfile.exe в консоли Sliver появилось уведомление о новой активной сессии. Подключение установлено автоматически, сессии присвоен идентификатор b6191a73 и кодовое имя NICE_SELECT. Успешно выполнено подключение к сессии с помощью команды use.

#### 2.6. Демонстрация контроля над системой

Получена информация о целевой системе: ОС Windows 10 версии 19045, архитектура x86_64, текущий пользователь user. Командой ps выведен список всех процессов, где обнаружен запущенный процесс safetyfile.exe с PID 11500. Выполнены базовые команды для проверки контроля: просмотр содержимого диска C:, получение информации о системе.

#### 2.7. Наблюдение за поведением процесса

Процесс safetyfile.exe оставался активным в диспетчере задач Windows на протяжении всего времени работы сессии. Он не вызывал подозрений у пользователя и не проявлял агрессивного поведения, маскируясь под легитимное системное приложение.

### 3. Выводы

3.1. Современные C2-фреймворки предоставляют полный цикл инструментов для удалённого управления системами, от генерации нагрузок до расширенной постэксплуатации.

3.2. Процесс safetyfile.exe, являясь фактически бэкдором, оставался незаметным для стандартного пользователя и продолжал работу в фоновом режиме, поддерживая постоянное соединение с C2-сервером.

3.3. Скрытность работы достигается за счёт легитимных техник выполнения и отсутствия явно вредоносных действий на этапе инициализации, что усложняет детектирование поведенческими анализаторами.

3.4. Практическое знакомство с C2-инфраструктурой позволяет лучше понимать механизмы современных кибератак и разрабатывать более эффективные меры защиты, учитывающие не только сигнатурный анализ, но и мониторинг сетевой активности и поведения процессов.

3.5. Работа в изолированной лабораторной среде обеспечила безопасное изучение инструментов постэксплуатации без риска для реальных систем.
